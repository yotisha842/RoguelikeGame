# RoguelikeGame

> Консольная roguelike-игра на Java в духе классической Rogue (1980): процедурно генерируемое подземелье, пошаговый бой, разные типы врагов, предметы и сохранение прогресса — всё в терминале.

Командный учебный проект Школы 21 (Java Bootcamp).

## Стек

- **Java 21**
- **Lanterna** — библиотека для отрисовки интерфейса и обработки ввода в терминале
- **Jackson** — сериализация состояния игры в JSON (сохранение / загрузка)
- **Gradle** (Kotlin DSL, `build.gradle.kts`)

## Геймплей

Игрок — авантюрист, спускающийся вглубь подземелья из **21 уровня**. Каждый уровень состоит из **9 комнат**, соединённых коридорами; расположение комнат, врагов и предметов генерируется процедурно, поэтому каждый забег уникален. Цель — найти на каждом уровне переход вниз и пройти все 21 уровень. Чем глубже — тем больше и опаснее враги, меньше полезных предметов и больше сокровищ. После гибели персонажа игра начинается заново, а результат забега попадает в таблицу рекордов.

Игра **пошаговая**: каждое действие игрока запускает ходы врагов.

### Характеристики персонажа

Здоровье, максимальное здоровье, сила и ловкость. Сила определяет базовый урон, ловкость влияет на вероятность попадания и скорость перемещения, максимальное здоровье — предел восстановления от еды. Предметы хранятся в рюкзаке (до 9 штук каждого типа).

## Враги

У каждого типа своя модель поведения, боя и передвижения по комнате:

| Враг | Символ | Особенности |
|---|---|---|
| **Зомби** | `z` | Низкая ловкость, высокое здоровье, средние сила и агрессия |
| **Вампир** | `v` | Высокие ловкость/агрессия/здоровье; при ударе снижает макс. здоровье игрока; первая атака по нему всегда мимо |
| **Призрак** | `g` | Высокая ловкость, низкое здоровье; телепортируется по комнате и периодически становится невидимым |
| **Огр** | `O` | Очень высокие сила и здоровье, ходит по две клетки; после атаки отдыхает ход, затем гарантированно контратакует |
| **Змея-маг** | `s` | Очень высокая ловкость; ходит по диагонали, меняя направление; удар может усыпить игрока на ход |
| **Мимик** | `m` | Маскируется под предметы (дополнительный тип врага) |

## Предметы

- **Сокровища** — копятся и формируют финальный счёт.
- **Еда** — восстанавливает здоровье.
- **Эликсиры** — временно повышают ловкость, силу или максимальное здоровье.
- **Свитки** — повышают ловкость, силу или максимальное здоровье навсегда.
- **Оружие** — добавляет силу; смена оружия меняет формулу расчёта урона.

## Бой

Инициируется движением в сторону врага и рассчитывается в три стадии:

1. **Попадание** — проверка на попадание по ловкости и скорости атакующего и цели.
2. **Урон** — рассчитывается по силе и модификаторам (например, от оружия).
3. **Применение** — урон вычитается из здоровья; при 0 персонаж или враг погибает.

За побеждённого врага выпадает количество сокровищ, зависящее от его характеристик.

## Туман войны

Сцена отображается в зависимости от исследованности:

- неисследованные комнаты и коридоры не видны;
- исследованные комнаты без игрока показаны только стенами;
- в текущей комнате видны стены, пол, враги и предметы;
- при подходе из коридора видимая область рассчитывается алгоритмами **Ray-Casting** и **Брезенхэма**.

## Сохранение и статистика

- Прогресс и характеристики сохраняются в **JSON** после каждого уровня — игра полностью восстанавливается после перезапуска.
- Ведётся **таблица рекордов**, отсортированная по количеству собранных сокровищ: уровень, число побеждённых врагов, съеденная еда, выпитые эликсиры, прочитанные свитки, попадания и промахи, пройденные клетки.

## Управление

| Клавиша | Действие |
|---|---|
| `W` `A` `S` `D` | Перемещение персонажа |
| `H` | Использовать оружие из рюкзака |
| `J` | Использовать аптечку |
| `K` | Использовать эликсир |
| `E` | Прочитать свиток |

## Архитектура

Чистая слоистая архитектура с разделением ответственности (принципы SOLID, инверсия зависимостей):

```
org.example/
├── presentation/  отрисовка сцены в терминале (Lanterna), обработка ввода
├── domain/        игровая логика: генерация уровней, сущности, бой, предметы
├── datalayer/     сохранение и загрузка состояния (JSON через Jackson)
└── StartGame.java точка входа
```

- **domain** не зависит от слоёв отображения и данных — вся игровая логика изолирована;
- **presentation** отвечает только за рендеринг и пользовательский ввод;
- **datalayer** — за персистентность прогресса и таблицы рекордов.

```bash

```
